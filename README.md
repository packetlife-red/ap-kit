# 応用情報技術者試験キット（ap-kit）

基本情報を取った人が、次に応用情報を目指すための学習ツール。

- **`dist/index.html`** — ゼロから読める入門レッスン ＋ 科目Aの計算問題を無限に生成するドリル ＋ 可視化シミュレータ（単一ファイル・依存ゼロ・PWA対応）
- **`skills/ap-kijutsu-check/`** — 科目B（記述式）の解答をClaudeが添削するスキル

> 仕組みを専門知識なしで知りたいときは **しくみ.md**（ローカルのみ）を読む。
> スマホから Macなしで使えるようにするには **[公開手順.md](公開手順.md)** に従う。

## すぐ使う

ブラウザで開くだけ。

```bash
open dist/index.html
```

スマホのホーム画面に置いてオフラインで使いたいときは、ローカルサーバ経由で開く（Service Workerは `file://` では動かないため）。

```bash
cd dist && python3 -m http.server 8765
```

→ `http://localhost:8765/` を開き、ブラウザの「ホーム画面に追加」。以降は機内モードでも解ける。

人に渡すときは `dist/ap_drill.html` の1ファイルを送れば動く（`index.html` と中身は同一。PWA機能だけが無効になる）。

**Macを起動せずスマホから使いたい場合は [公開手順.md](公開手順.md)。** GitHub Pages に置くとURLが固定され、成績も確実に残る。

## 何が入っているか

### はじめから（初学者向けレッスン・3本）

**用語をひとつも知らない状態から読み始められる**一本道のモード。初回起動時はこのタブが開く。

| # | レッスン | 扱う分野 |
|---|---|---|
| 1 | システムはどれくらい動いているか | 稼働率 |
| 2 | コンピュータの数の数え方 | 2進数 |
| 3 | ファイルを送るのにかかる時間 | 伝送時間 |

各レッスンは **読む → 一緒に解く → 自分で解く** の3段。

- **読む** … 問題は出さない。ATM・電車の乗り換えなど身近な例から入り、用語は初出時に説明する
- **一緒に解く** … 例題を穴埋めで追う。**採点しない。**「答えを見る」を押してよい
- **自分で解く** … 初めて自力。ヒント常時表示。**間違えても正解を出さず**、押した肢だけ落として別のヒントで再挑戦させる

数値は暗算できるものだけを使う（0.9 × 0.9 など）。ドリルのように乱数生成はせず全文が固定で、説明文と数値が必ず一致する。

**ここでの正誤は成績に記録しない。** 記録するのは「どこまで進んだか」だけ。まだ習っていないことを間違えさせて減点するのは学習ではないため。修了後に「本番の問題を解いてみる」で対応するドリル分野へ飛べる。

### 計算ドリル（14分野）

| 分野 | 出題パターン |
|---|---|
| 稼働率・信頼性 | 直列 / 並列 / 複合 / MTBF・MTTR |
| 待ち行列（M/M/1） | 待ち時間 / 応答時間 / 利用率 |
| キャッシュ実効アクセス時間 | 実効時間 / ヒット率の逆算 / 高速化率 |
| CPI・MIPS・命令ミックス | 加重平均CPI / MIPS / 実行時間 |
| 伝送時間・データ量 | 伝送時間 / 標本化・音声データ量 / 必要回線速度 |
| サブネット・CIDR | 収容ホスト数 / ネットワークアドレス / ブロードキャスト / 必要プレフィクス長 |
| 基数変換・2の補数 | 基数変換 / 2の補数 / 表現範囲 / シフト演算 |
| PERT・クリティカルパス | 最短所要日数 / 余裕日数 / 遅延の影響（アローダイアグラム図つき） |
| ディスクアクセス・RAID | アクセス時間（シーク＋回転待ち＋転送） / RAID実効容量 / 処理件数 |
| ハフマン符号・圧縮率 | 平均符号長 / 圧縮率 / 固定長との比較 |

| 損益分岐点・ROI・NPV | 損益分岐点 / 目標利益 / ROI / 正味現在価値 |

### 可視化シミュレータ（3本）

- **待ち行列** — ρを上げると待ち時間が爆発する様子をアニメーションで体感。実測値と理論値 `Tw=ρ/(1−ρ)·Ts` を並べて表示
- **サブネット** — プレフィクス長を動かすと32ビットのどこで区切られるかが色分けで動く
- **ページ置換** — 同じ参照列にFIFO・LRU・OPTを流し、フォールト数を比較

各シミュレータから対応するドリル分野へ飛べる（体感 → 演習）。

## 解説の作り（explain）

答え合わせのあとに出るのは、式の羅列ではなく**4段構成の解説**。

| ブロック | 内容 |
|---|---|
| **この問題が聞いていること** | 用語の意味から。MTBFが何の略かを知らなくても読み始められる |
| **なぜその式になるのか** | 公式を暗記させない。理屈から式を導く（ここが本体） |
| **実際に計算する** | 数字を1行ずつ追える形。途中の値をすべて見せる |
| **ここを間違えやすい** | 混同する相手を名指しし、検算のコツを添える |

式だけを見たい人向けに、従来の `steps` は「式だけを見る」の折りたたみに残してある。

ジェネレータ側は `explain('ask'|'why'|'calc'|'trap', 見出し, 本文)` を配列で返すだけ。本文では `**太字**` と改行が使える。`explain` を持たない分野は、従来どおり `steps` がそのまま表示される（後方互換）。

**本文は手書きなので、機械検証で守っている**：変数の埋め込みミス（`undefined`／`NaN` の混入）、`**` の閉じ忘れ、本文が短すぎるもの、そして **calcブロックに書かれた答えが実際の正解と一致するか**。この最後のチェックは、わざと答えを壊して検出されることを確認済み。

### 実装済みの分野

- ✅ 稼働率・信頼性（直列 / 並列 / 複合 / MTBF・MTTR の4パターン）
- ⬜ 他13分野は未着手（`steps` のみ）

## 設計の芯

**過去問の暗記が効かないこと。**

全問をパラメータ乱数から生成し、**誤答選択肢を「典型的なミスをするとこの値になる」から作っている**。ランダムなダミー値は使わない。

- 稼働率で並列を直列として計算した値
- 待ち行列で待ち時間と応答時間を取り違えた値
- サブネットでネットワーク／ブロードキャストを引き忘れた値

消去法で当てられないうえ、間違えたときに「なぜその値になったのか」が解説される。ここが学習効果の中心。

出題は**全問その場で自動生成**しており、IPA過去問の問題文は一切含んでいない。

## 開発

このMacには Node.js が入っていないため、**macOS標準の JavaScriptCore（`jsc`）と Python 3 だけ**で完結するようにしてある。npm依存はゼロ。

```bash
# ビルド（src/ → dist/index.html ＋ ap_drill.html）
python3 tools/build.py

# 自動検証（ジェネレータ154万件 ＋ レッスン）
./tools/verify.sh

# 出題を端末で目視
./tools/preview.sh              # 全分野を1問ずつ
./tools/preview.sh reliability 5   # 指定分野を5問
```

**`jsc` は日本語を含む絶対パスを開けない**ので、`tools/*.sh` はプロジェクト直下へ `cd` してから相対パスで呼んでいる。直接叩くときも同様にすること。

### 構成

```
src/
  core/           ← UIに依存しない層。将来アプリ化しても残る
    rng.js          seed付き乱数（同じseed＝同じ問題）
    store.js        保存層の抽象化（localStorageを直接叩かない）
    genkit.js       選択肢の組み立て・登録・生成
    generators/     分野ごとに1ファイル
  learn/          ← はじめからモード（初学者向け）
    lessons.js      レッスン本文。全文が手書きの固定データ
    app.js          レッスンを進める画面
  ui/             ← DOMに触る層。載せ替え対象
  sim/            可視化シミュレータ
tools/
  build.py             結合ビルド（Python標準ライブラリのみ）
  verify.mjs           ジェネレータの自動検証
  verify-lessons.mjs   レッスンの自動検証
  preview.mjs          端末プレビュー
dist/             配布物
```

`learn/` は `ui/` とは別に切ってある。ドリルが「即採点して次へ流す」設計なのに対し、こちらは「採点しない・答えを出さない」と方針が正反対で、同じ画面コードに同居させると条件分岐だらけになるため。

将来React化やネイティブ化するときは、`ui/` を捨てて `core/` をそのまま使う。保存先を変えるなら `store.js` だけ差し替える。

### ジェネレータを追加する

1. `src/core/generators/新分野.js` を作り `register({ id, name, category, gen(rng) })` を呼ぶ
2. `src/core/generators/index.js` に `import` を1行足す
3. `./tools/verify.sh` を通す

`gen(rng)` は `{ question, answer, distractors, steps, format?, hint?, note?, svg? }` を返す。選択肢のシャッフルや重複除去は `genkit.js` が引き受ける。

**誤答は4〜5個用意する。** `buildChoices` は先頭から3つ採用し、正解と表示が重複するものは捨てるため、多めに用意しておくとパラメータ次第の衝突を自動で吸収できる。

## 検証について

「推定より実測」に従い、目視だけで完了としていない。

- **自動検証** — 全ジェネレータを各5000回生成し、選択肢の重複、正解の整合、解説の最終値と正解の一致、`explain` 本文の健全性、**選択肢が読める桁数か**、分野固有の範囲などをアサート（1,545,024件・全通過）
- **独立実装との突き合わせ** — 稼働率・2の補数・サブネット（Pythonの `ipaddress`）・EVM・NPV・ページ置換・ディスクアクセス時間・期待値の各値を、Pythonで別途計算して一致を確認
- **ハフマン符号** — クラフトの不等式（Σ2^(-l) = 1）で木の正当性を確認し、さらにPythonのヒープ実装と平均符号長が一致することを照合
- **待ち行列** — 40,000秒ぶんシミュレーションし、ρ=0.3〜0.8で実測値が理論値と2〜7%以内で一致することを確認（ρ≧0.85は収束が遅く、ずれが残るのは理論どおりの挙動）
- **ブラウザ実測** — 外部リクエストゼロ、390px幅ではみ出し要素0、**サーバを止めた状態でドリル・レッスンとも動作すること**を実測（PWAのオフライン動作）
- **レッスン** — 3レッスンを画面上で最後まで自動走行させ、各問でわざと誤答して**正解が漏れないこと**を確認。加えて `verify-lessons.mjs` が全問について「hint / hint2 に正解の文字列が含まれていないか」を機械検査する（この検査で実際に1件の漏れを検出し、問題を差し替えた）

### 既知の注意点

- **トップレベルの識別子は全ファイルで一意にすること。** 単一スコープに連結するため、別ファイルに同名の関数があると実行時に落ちる。`build.py` が検出して止めるが、命名時に意識しておくと早い
- ρ≧0.85の待ち行列は実測が理論値に収束するまで時間がかかる。バグではない

## 科目B添削スキル

`~/.claude/skills/ap-kijutsu-check/` に配置済み（`skills/` 配下は配布用マスターコピー。**ルールを直したら両方を同期する**）。

Claude Codeで問題文と自分の解答を貼れば、採点要素に分解して部分点を出し、字数を実測して改善版を提示する。

## 試験の前提（2026年7月時点）

2026年度（令和8年度）から応用情報はCBT方式に移行。午前→**科目A**（150分・80問四択）、午後→**科目B**（150分・11問中5問、問1情報セキュリティ必須＋4問選択・記述式）に名称変更。出題形式・配点・合格基準は据え置きで、**記述解答がキーボード入力**になった。
